# Fast Track: set-field sperrt Gate-Schlüssel, BatchMode nur für OpenSSH (#379)

## Problem

`workflow.py set-field` setzte jeden Schlüssel ungeprüft. `set-field workflow_type feature-fast`
entzog einen freigegebenen `feature`-Workflow dem Adversary-Gate: Der feature-fast-Zweig von
`_validate_transition` prüft beim Abschluss kein Verdict, `finish` archivierte ohne Nachweis.
Zweiter Punkt (LOW): Der Banner-Fetch hängte `-oBatchMode=yes` auch an nicht-OpenSSH-Clients
(plink), der Fetch scheiterte und die Warnung „hinter origin“ fiel still weg.

## Scope

- `core/hooks/workflow.py`: `cmd_set_field` sperrt Gate-Schlüssel mit eigenem Befehl; `workflow_type` nur `feature`/`feature-fast`, Herabstufung nach der Freigabe (`spec_approved` oder ab `phase4_approved`) nur mit Override-Token; `base_commit` gesperrt, `spec_file` nach der Freigabe nur mit Override
- `core/hooks/session_banner.py`: BatchMode nur bei Programmname `ssh`; plink/putty und alleiniges `GIT_SSH` bleiben unberührt; `core.sshCommand` dient als Basis
- Nicht enthalten: Sperre für `adversary_verdict` (`qa_gate.py` schreibt es per set-field; Commit und Phase 8 verlangen ohnehin den gestempelten Dialog-Nachweis)

## Definition of Done

Beide Defekte sind durch Tests belegt, die ohne die Änderung rot sind; die volle Suite bleibt grün.

## Acceptance Criteria

- **AC-1:** Given ein `feature`-Workflow ab phase4_approved, When `set-field workflow_type feature-fast` ohne Override-Token läuft, Then blockt der Befehl, der Typ bleibt `feature` und `finish` archiviert nicht.
- **AC-2:** Given ein gültiger Override-Token des Users oder eine Phase vor phase4_approved, When `set-field workflow_type feature-fast` läuft, Then wird der Typ gesetzt.
- **AC-3:** Given ein Gate-Schlüssel mit eigenem Befehl (z. B. `current_phase`, `spec_approved`, `red_test_done`), When `set-field` ihn setzen soll, Then blockt der Befehl, nennt den richtigen Befehl und der State bleibt unverändert.
- **AC-4:** Given `GIT_SSH_COMMAND=plink -batch`, `GIT_SSH_VARIANT=plink` oder nur `GIT_SSH`, When der Banner git aufruft, Then wird kein `-oBatchMode=yes` angehängt; bei `ssh` weiterhin schon.
- **AC-5:** Given ein freigegebener Workflow, When er per `phase` vor phase4 zurückgesetzt wird und danach `set-field workflow_type feature-fast` läuft, Then blockt der Befehl weiterhin.
- **AC-6:** Given ein freigegebener Workflow ohne Override-Token, When `set-field spec_file` oder `set-field base_commit` läuft, Then blockt der Befehl; `spec_file` bleibt vor der Freigabe frei setzbar.
- **AC-7:** Given `core.sshCommand=plink -batch` in der Git-Config, When der Banner git aufruft, Then setzt er kein `GIT_SSH_COMMAND`; bei `core.sshCommand=ssh -i k` hängt er BatchMode an dieses Kommando an.
