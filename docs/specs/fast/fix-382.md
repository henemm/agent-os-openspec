# Fast Track: session_banner liest core.sshCommand nur für den Fetch (#382)

## Problem

`session_banner._git` las vor jedem Git-Aufruf (ca. 5 pro Banner) `git config --get core.sshCommand`
mit festem Timeout von 1 s. Nur der Fetch nutzt ssh. Hängt `git config` (langsames Dateisystem,
Netz-Home), kamen bis zu 5 s auf das 4-s-Budget, und der Hook-Timeout von 5 s schnitt den Banner ab.

## Scope

- `core/hooks/session_banner.py`: `_git` ruft `_batch_ssh` nur bei einem Fetch auf; das Config-Lesen ist auf `min(1, Timeout des Aufrufs)` begrenzt und zählt zu diesem Timeout
- `tests/test_banner_behind_origin_185.py`: der BatchMode-Test nutzt einen Fetch statt `git --version`
- Nicht enthalten: BatchMode für Wrapper wie `env FOO=1 ssh` (bleibt bewusst aus)

## Definition of Done

Der Fundfall ist durch einen Test belegt, der ohne die Änderung rot ist; die volle Suite bleibt grün.

## Acceptance Criteria

- **AC-1:** Given ein `_git`-Aufruf ohne `fetch`, When er läuft, Then startet kein `git config --get core.sshCommand`.
- **AC-2:** Given ein Fetch, When `_git` läuft, Then wird `core.sshCommand` genau einmal mit Timeout ≤ 1 s gelesen und der Fetch bekommt `-oBatchMode=yes`.
- **AC-3:** Given ein Fetch mit einem Timeout unter 1 s, When `_git` läuft, Then ist das Config-Timeout nicht größer als dieses Timeout.
- **AC-4:** Given das Config-Lesen braucht Zeit, When der Fetch startet, Then bekommt er nur das verbleibende Timeout.
