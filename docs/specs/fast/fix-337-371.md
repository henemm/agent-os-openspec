# Fast Track: Abschluss prüft auch in Phase 8 (#337), Banner-Fetch ohne Waisen (#371)

## Problem

#337: `workflow.py complete`/`finish` archivierte einen Workflow, der bereits auf
`phase8_complete` stand, ohne jede Prüfung — `_validate_transition` kehrte bei gleicher Phase
sofort zurück. #371: Nach dem Timeout des Banner-Fetch (#185) liefen Kindprozesse (remote-http,
Credential-Helper, ssh) als Waisen weiter; eine eigene `GIT_SSH_COMMAND` des Users lief ohne
BatchMode. Beide aus der Backlog-Triage, klein und lokal.

## Scope

- `core/hooks/workflow.py`: `_validate_transition` prüft Phase 8 auch bei gleicher Phase
- `core/hooks/session_banner.py`: eigene Prozessgruppe, Gruppen-Kill bei Timeout, BatchMode anhängen
- Nicht enthalten: Abschalten von Credential-Helpern (würde die Warnung bei privaten Repos verlieren)

## Definition of Done

Beide Defekte sind durch Tests belegt, die ohne die Änderung rot sind; die volle Suite bleibt grün.

## Acceptance Criteria

- **AC-1:** Given ein Workflow (Typ feature) auf phase8_complete ohne Adversary-Verdict, When `workflow.py complete` oder `finish` läuft, Then blockt der Abschluss und der Workflow wird nicht archiviert.
- **AC-2:** Given ein Remote, dessen Transport hängt, When der Banner-Fetch in den Timeout läuft, Then kehrt `behind_lines` in unter 5 s zurück und kein Kindprozess läuft weiter.
- **AC-3:** Given eine eigene `GIT_SSH_COMMAND` ohne BatchMode, When der Banner git aufruft, Then läuft ssh mit `-oBatchMode=yes`.

## Test Plan

- `tests/test_complete_recheck_337.py` (AC-1), `tests/test_banner_behind_origin_185.py` (AC-2, AC-3), volle Suite
